# CLI

The `fieldproof` command line interface is the entry point of the scenario engine
([01-architecture.md](../plan/01-architecture.md#l4-scenario-engine)). It is installed by the
engine package: `uv run --project engine fieldproof ...` from the repository, or `fieldproof ...`
inside an environment where the package is installed.

| Command | Produced by | Description |
| --- | --- | --- |
| `fieldproof --version`, `-V` | P0-T07 | print `fieldproof <version>` and exit; the version is the repository version of `version.txt` |
| `fieldproof --help` | P0-T07 | list the commands and options; running `fieldproof` without arguments prints the same |
| `fieldproof validate <scenario>...` | P1-T05, P2-T03 | validate scenario files against schema v0 and resolve them against the workspace: the world file and its frames, every vehicle manifest, the timeline's entries through their events' `plan` hooks ([scenarios.md](scenarios.md), [events.md](events.md)); no container is started; a warning per event plugin that could not be loaded; options `--config`, `--set path=value` (override a value of the document before it is validated, repeatable; [matrix.md](matrix.md#scenario-overrides)) |
| `fieldproof run <scenario>` | P1-T05, P1-T06, P1-T07, P2-T01 | run a scenario with the Docker backend: simulator (and the run's discovery server with `--discovery server`), the bridges, the recorder and the vehicles of a fleet in parallel with readiness gates and `depends_on` ordering, each vehicle under its namespace and budget ([scenarios.md](scenarios.md#fleets)), the timeline with its entries started at their time and the assertions evaluated as it runs and, when `outputs.video` is set, the world's camera recording it ([scenarios.md](scenarios.md#video)), teardown, the reports (Markdown, JSON, JUnit); writes `runs/<run_id>/` ([scenarios.md](scenarios.md#running-a-scenario), [assertions.md](assertions.md)); prints the verdict of every assertion after the status line and the video's path; options `--config`, `--runs-dir`, `--run-id`, `--render`, `--domain-id` (the run's `ROS_DOMAIN_ID`, derived from the run id by default), `--network`, `--discovery multicast\|server`, `--check-contracts` (run every vehicle's bridge contract check), `--keep`, `--quiet`, `--dry-run`, `--video`/`--no-video` (override `outputs.video`), `--seed` (override the scenario's seed, [time.md](time.md)), `--set path=value` (override any value of the scenario file before it is validated, repeatable: `--set time.rtf=2 --set 'vehicles[ugv1].resources.cpus=1'`; the run records the effective document and the overrides, [matrix.md](matrix.md#scenario-overrides)); the run records itself in the run database at its end (`fieldproof.sqlite` in the runs directory, or `--database FILE`; [matrix.md](matrix.md#the-run-database)) |
| `fieldproof schema` | P1-T05 | print the JSON Schema of a scenario file (`make scenario-schema` writes `engine/schemas/scenario.schema.json`), the timeline entries of every registered event included |
| `fieldproof events` | P2-T03 | list the timeline actions the engine knows: the built-in events and the plugins installed next to it, with their source, summary and parameters ([events.md](events.md)); option `--json`; exit code 2 when a plugin could not be loaded, with the reason |
| `fieldproof assertions` | P2-T05 | list the assertion types the engine knows (the built-in library and the plugins installed next to it, with their source, summary, parameters and metrics) and the KPI collectors ([assertions.md](assertions.md)); option `--json`; exit code 2 when a plugin could not be loaded, with the reason |
| `fieldproof report <run>` | P1-T06, P1-T07, P2-T06 | render the report of a run from its `run.json`: a run directory, the file itself, or a run id under the workspace's runs directory ([assertions.md](assertions.md#reports)); options `--format md\|html\|json\|junit` (Markdown by default; `html` the self-contained page of [matrix.md](matrix.md#html-reports); `junit` is the JUnit XML document CI consumes, [ci.md](../setup/ci.md#scenario-tests)), `--write` (rewrite `report.md`, `report.html`, `report.json` and `junit.xml` in the run directory), `--config` |
| `fieldproof clock <run> status\|pause\|resume\|step` | P2-T04 | the simulator's clock of a running run (or one kept with `--keep`), found by its directory or id: `status` prints whether the world is paused, its simulation time, iteration and real-time factor (`--json` for the statistics), `pause`, `resume` and `step` (`--steps N`, or `--seconds S` converted with the world's physics step) act on its control service ([time.md](time.md#pausing-resuming-and-stepping)); options `--config`; exit code 1 when the world refuses, 2 when the run has no running simulator |
| `fieldproof compare <run-a> <run-b>` | P2-T04 | compare the vehicles' ground-truth trajectories of two runs of a scenario in timeline time: per vehicle the largest deviation and when, the mean and the final one ([time.md](time.md#comparing-two-runs)); options `--tolerance-m` (0.25 m), `--json`, `--config`; exit code 0 when every vehicle stays within the tolerance, 1 otherwise, 2 when a run cannot be compared |
| `fieldproof log info <log>` | P2-T07 | what a field log holds (an MCAP file or a rosbag2 directory): topics, types, message counts, span and storage, from its summary without decoding a message; what a replay scenario's `source.vehicles` mapping is written from ([replay.md](replay.md#logs)); option `--json`; exit code 2 when the log cannot be read |
| `fieldproof log synth <out.mcap>` | P2-T07 | write the synthetic field log of the reference UGV (a hall with crates, a driven rectangle, drifting wheel odometry, exact ground truth; `make replay-log` writes the one the replay example plays); options `--seconds`, `--seed`, `--start-x`, `--start-y`, `--start-yaw`, `--force`, `--json` |
| `fieldproof matrix <matrix>` | P2-T06 | run a matrix file (`kind: Matrix`: a scenario over `parameters` and `seeds`, [matrix.md](matrix.md)): every case resolved first, then run as its own `fieldproof run` process, as many at once as the host's cores and memory fit (or `--parallel N`), a failed case retried (`--retries N`) and flagged when flaky (`--fail-on-flaky` makes that a failure), one `junit.xml`, `report.md` and `report.html` for the whole in `runs/<matrix_id>/` with every attempt's run directory, every run and the matrix recorded in the run database; options `--config`, `--runs-dir`, `--parallel`, `--retries`, `--fail-on-flaky`/`--allow-flaky`, `--render`, `--only PATTERN` (cases by id or name, glob, repeatable), `--summary FILE` (append the Markdown report; `$GITHUB_STEP_SUMMARY` by default), `--dry-run` (the cases, their demands and the schedule as JSON); exit code 0 when every case passed, 1 otherwise, 130 when interrupted (every running case interrupted first), 2 when the matrix or a case cannot be resolved |
| `fieldproof runs list` | P2-T06 | the runs the workspace's run database knows, newest first, one line each: run id, verdict, scenario, start, duration, seed, assertion counts and, for a matrix's run, its case, attempt and flakiness ([matrix.md](matrix.md#the-run-database)); options `--scenario`, `--status`, `--matrix ID`, `--limit`/`-n`, `--json`, `--config`, `--runs-dir` (whose database), `--database FILE` |
| `fieldproof runs show <run>` | P2-T06 | one run's facts, assertions, KPIs and artefacts from the database (a run id or a unique prefix) or from a run directory or its `run.json`; options `--json` and the database options |
| `fieldproof runs diff <run-a> <run-b>` | P2-T06 | compare two runs: the scenario document and seeds, the overrides that differ, the durations with their deltas, every assertion whose verdict changed (regressed, fixed) and every KPI of either run with both values, the delta and the percentage; options `--json` and the database options; exit code 0 |
| `fieldproof runs index [<root>]` | P2-T06 | read the run directories (and `matrix.json` records) under a directory (the runs directory by default) into the database: runs from before the database or copied from CI artefacts; option `--json` and the database options |
| `fieldproof bridge gen <robot.yaml>` | P1-T03 | write the ros_gz bridge bundle of a vehicle: bridge configurations, adapter parameters, contract and launch file ([bridge.md](bridge.md#generating-a-bundle)); options `--out`, `--namespace`, `--frame-prefix`, `--no-clock`, `--no-robot-state-publisher`, `--without` |
| `fieldproof manifest validate <robot.yaml>...` | P1-T04, P2-T08 | validate vehicle manifests against schema v0 with their `extends` chain resolved ([manifest.md](manifest.md)); `--partial` accepts a manifest meant only to be extended; `--config` names the workspace whose reference models an `extends: fieldproof:<model>` resolves against (default: the nearest `fieldproof.toml` above the manifest) |
| `fieldproof vehicle init [DIR]` | P2-T08 | scaffold a vehicle repository ([onboarding.md](onboarding.md#what-init-writes)): `robot.yaml` extending a reference model by name, `fieldproof.toml`, a smoke scenario, a bringup package with a status node, the generated build context, a Makefile and a README; options `--name` (default: the directory's name), `--model` (`ugv_ref`), `--package` (`<name>_bringup`), `--launch` (`bringup.launch.py`), `--no-package` (a repository that has its code), `--force` (overwrite), `--config`; exit code 2 when a file exists already or a name is not a name |
| `fieldproof manifest schema` | P1-T04 | print the JSON Schema of a manifest file (`make manifest-schema` writes `engine/schemas/robot.schema.json`) |
| `fieldproof vehicle dockerfile <robot.yaml>` | P1-T04, P2-T08 | write the build context of a vehicle image: Dockerfile, entry point, resolved manifest, `vehicle.repos` ([manifest.md](manifest.md#vehicle-images)); the Dockerfile's base image is the manifest's `runtime.build.base` or the workspace's `base-ros2` image at its prefix and tag; options `--out`, `--config` |
| `fieldproof vehicle build <robot.yaml>` | P1-T04, P2-T08 | write the context and run `docker buildx build`; options `--context`, `--tag`, `--base-image` (overrides the manifest's and the workspace's), `--no-cache`, `--progress`, `--docker-arg`, `--dry-run`, `--config` |
| `fieldproof vehicle run <robot.yaml> [-- CMD...]` | P1-T04, P2-T01 | `docker run` the vehicle image with the manifest's budget (`cpus`, `cpuset`, `memory`, `pids`), environment and DDS profile on the `fieldproof` network; options `--name`, `--network`, `--domain-id`, `--namespace` and `--frame-prefix` (into the environment and the launch's `namespace_arg`/`frame_prefix_arg`), `--detach`, `--keep`, `--image`, `--env`, `--docker-arg`, `--dry-run` |
| `fieldproof vehicle wait <robot.yaml>` | P1-T04 | wait until the running vehicle container satisfies the manifest's `runtime.ready` conditions, through the image's readiness probe ([manifest.md](manifest.md#the-readiness-probe)); exit code 1 with the pending conditions on timeout; options `--name`, `--timeout`, `--interval`, `--quiet`, `--dry-run` |
| `fieldproof cockpit` | P3-T01 | serve the cockpit against the local engine |

Exit codes: `0` on success, `1` on a failed scenario or assertion (also a run that timed out or
could not start), `2` on a usage error (Typer's convention), `130` on a run interrupted by Ctrl-C
or SIGTERM. Output is Rich-formatted on a terminal and plain when piped.
